# FastPDF

[English](README.md) · **ไทย**

โปรแกรมอ่าน PDF ขนาดเบา รวดเร็ว และใช้ส่วนติดต่อขั้นต่ำสำหรับ **Windows** สร้างด้วย
Win32 + Direct2D + PDFium พร้อมโหมดนำเสนอ จับภาพหน้าเอกสาร แปลง PDF ⇄ ภาพ พิมพ์แบบ native และค้นหาข้อความในเอกสาร

ไม่มีตัวติดตั้ง ไม่มีบริการที่รันอยู่เบื้องหลัง และไม่ได้เผยแพร่ผ่าน app store คุณสร้างโปรแกรมจาก repository นี้เอง หรือนำโฟลเดอร์แบบพกพาที่สคริปต์แพ็กเกจสร้างไว้ไปรัน

## FastPDF คืออะไร

FastPDF เปิดไฟล์ PDF ผ่านกล่องโต้ตอบ File Open แบบ native ของ Windows
(**Ctrl+O** หรือ **File > Open...**) ด้วยการ **ลากแล้ววาง** หรือโดยตรงจาก
command line (`FastPDF.exe "path\to\file.pdf"`) โหลดเอกสารผ่าน
adapter `fastpdf_pdfium` แล้วเรนเดอร์หน้าเอกสาร **นอกเธรด UI** ลงเป็น bitmap
BGRA บน CPU ที่ไม่มีการแก้ไข จากนั้นหน้าต่าง Direct2D จะแสดงผลในลักษณะ
**ต่อเนื่องหนึ่งคอลัมน์**

รองรับการเลื่อนด้วยล้อเมาส์ นำทางด้วยแป้นพิมพ์ Fit Width / Fit Page / 100% /
กำหนดระดับซูมเอง (ถูกจำกัดไว้ที่ 25%–800%) และการซูมโดย **จุดศูนย์กลางอยู่ที่ตัวชี้เมาส์** ด้วย Ctrl + ล้อเมาส์ พร้อมระบบ **page anchor** ที่คงตำแหน่งตามเหตุผลไว้เมื่อซูมหรือปรับขนาดหน้าต่าง ภาพจะไม่กระโดดไปหน้าอื่น แถบสถานะแสดงชื่อไฟล์ หน้าปัจจุบัน และระดับซูม

เมื่อปรับขนาดหน้าต่างหรือย้ายไปจอที่มี DPI ต่างกัน ระบบจะจัดวางและเรนเดอร์ใหม่อย่างถูกต้อง ส่วนติดต่อตอบสนองต่อเนื่องขณะเปิดและเรนเดอร์เอกสาร และฟื้นตัวอัตโนมัติเมื่ออุปกรณ์ Direct2D สูญหาย (เช่น เปลี่ยนความละเอียดจอ) ไฟล์ที่หาไม่พบ อ่านไม่ได้ เสีย หรือตั้งรหัสผ่าน จะแสดงข้อความสั้น ๆ ที่ไม่ใช่ศัพท์ทางเทคนิค

## คุณสมบัติหลัก

- **อ่านแบบต่อเนื่อง** — จัดวางหนึ่งคอลัมน์ เรนเดอร์ภาพย่อมาก่อนแล้วค่อยแทนที่ด้วยภาพคุณภาพเต็ม
- **การซูม** — Fit Width, Fit Page, 100%, กำหนดเอง 25%–800% และ Ctrl + ล้อเมาส์ที่ยึดตำแหน่งตัวชี้
- **โหมดนำเสนอ (F11)** — เต็มจอไร้ขอบ จัดหน้าพอดีทีละหน้า เรนเดอร์หน้าข้างเคียงล่วงหน้าจึงเปลี่ยนหน้าได้เร็วมาก
- **จับภาพหน้าเอกสาร (Ctrl+S)** — ลากกรอบเลือกข้ามหลายหน้าได้ คัดลอกลงคลิปบอร์ดเป็น `CF_DIBV5` และ PNG พร้อมบันทึกเป็นไฟล์ PNG ในขั้นตอนเดียว
- **แปลง PDF เป็น PNG** — ส่งออกหลายหน้าที่คุณภาพ Standard (150 DPI) หรือ High (300 DPI) มีแถบความคืบหน้า ยกเลิกได้ และไม่เขียนทับไฟล์เดิม
- **แปลงภาพเป็น PDF** — รวมไฟล์ PNG / JPEG / BMP เป็น PDF เดียว จัดลำดับใหม่ได้ เลือกทิศทางหน้า A4 อัตโนมัติ และคงสัดส่วนภาพเดิม
- **พิมพ์แบบ native (Ctrl+P)** — ดูตัวอย่างก่อนพิมพ์ เลือกเครื่องพิมพ์ ระบุช่วงหน้า ปรับการขยายและทิศทาง รวมถึงยกเลิกได้
- **ค้นหาข้อความแบบทันที (Ctrl+F)** — ค้นบนเธรดพื้นหลัง นำทางระหว่างผลลัพธ์ และไฮไลต์กรอบตำแหน่งข้อความ
- **ไฟล์ที่เปิดล่าสุด** — เก็บได้สูงสุด 10 รายการ พร้อมหน้า ตำแหน่งการมอง และระดับซูมเดิม
- **ข้อมูลวินิจฉัย (Ctrl+D)** — ตัวเลขการทำงานแบบสดบนแถบสถานะ และไฟล์บันทึกบนเครื่องแบบหมุนเวียน
- **แพ็กเกจแบบพกพา** — สร้าง `dist\FastPDF-<version>-win-x64.zip` พร้อมรายการแฮช SHA-256 และเอกสารสิทธิ์บุคคลที่สาม

## แพลตฟอร์มที่รองรับและข้อกำหนด

**สำหรับใช้งาน FastPDF**

- Windows 10 หรือ Windows 11 แบบ **64 บิต (x64)**
- ไฟล์ `FastPDF.exe` ต้องอยู่ในโฟลเดอร์เดียวกับ `pdfium.dll` (จำเป็นสำหรับฟีเจอร์ PDF
  ดู [การเผยแพร่ไฟล์สำเร็จรูป](#การเผยแพร่ไฟล์สำเร็จรูป))
- ไม่ต้องใช้ตัวติดตั้ง ไม่ต้องใช้สิทธิ์ผู้ดูแลระบบ และตอนใช้งานจริงไม่ต้องมี
  .NET หรือ Visual Studio

**สำหรับสร้าง FastPDF จากซอร์ส**

- Visual Studio 2022 (หรือ Build Tools 2022) พร้อมเวิร์กโหลด *Desktop development
  with C++* (MSVC v143)
- Windows SDK >= 10.0.19041
- CMake >= 3.24 (มาพร้อมกับ Visual Studio หรือดาวน์โหลดจาก cmake.org)
- C++20 (กำหนดไว้ใน `CMakeLists.txt`)
- อาร์ติแฟกต์ PDFium เวอร์ชันตรึง (pinned) ที่คุณดาวน์โหลดและตรวจสอบเอง
  ([การสร้างโปรแกรมจากซอร์ส](#การสร้างโปรแกรมจากซอร์ส)) — FastPDF ไม่ดาวน์โหลดให้ และจะไม่สลับไปใช้ PDFium ที่มีอยู่ในระบบโดยอัตโนมัติ

**หมายเหตุ**

- โปรเจกต์ปฏิเสธการ configure ที่ไม่ใช่ x64 (`CMakeLists.txt` จะหยุดพร้อมข้อความระบุสาเหตุชัดเจน)
- การ build ใช้ MSVC CRT แบบ **dynamic** ตามค่าเริ่มต้น (ไม่มีการกำหนดค่า
  runtime-library ทับไว้ในไฟล์ CMake) ยัง **ไม่ได้ทดสอบ** ว่าเครื่องที่ไม่มี
  Visual C++ 2015–2022 redistributable จะรัน `FastPDF.exe` จากแพ็กเกจได้หรือไม่ จึงถือเป็นการตรวจสอบด้วยมือที่ยังไม่ยืนยันผล
- ส่วนติดต่อของโปรแกรม (เมนู กล่องโต้ตอบ และข้อความต่าง ๆ) มีเฉพาะภาษาอังกฤษ

## เริ่มใช้งานเร็ว การรัน FastPDF

หากคุณมีโฟลเดอร์หรือไฟล์ ZIP ของ FastPDF อยู่แล้ว (สร้างเองจาก
[การสร้างแพ็กเกจเผยแพร่](#การสร้างแพ็กเกจเผยแพร่) หรือคัดลอกจากเครื่องที่สร้าง):

1. แตกไฟล์หรือวางไว้ที่ใดก็ได้ เช่น `C:\Tools\FastPDF\` หรือใน USB drive โดยเก็บ
   `FastPDF.exe` และ `pdfium.dll` ให้อยู่ในโฟลเดอร์เดียวกัน
2. ดับเบิลคลิกที่ `FastPDF.exe` ได้ทันที ไม่มีการติดตั้งและไม่เขียนรีจิสทรี
3. ตอนเปิดโปรแกรม แถบสถานะจะแสดงข้อความ
   `Press Ctrl+O or File > Open to open a PDF.`
4. เมื่อต้องการย้ายหรือลบโปรแกรม ให้ย้ายหรือลบโฟลเดอร์นั้นได้เลย สถานะต่อผู้ใช้มีเพียงรายการที่อธิบายใน [ไฟล์ที่ FastPDF เขียนลงเครื่องคุณ](#ไฟล์ที่-fastpdf-เขียนลงเครื่องคุณ)

ถ้ายังไม่มีไฟล์ที่ build แล้ว ไปที่ [การสร้างโปรแกรมจากซอร์ส](#การสร้างโปรแกรมจากซอร์ส)

## การเปิดไฟล์ PDF

1. เรียก `FastPDF.exe`
2. กด **Ctrl+O** (หรือ **File > Open...**) แล้วเลือกไฟล์ `.pdf` ตัวกรองของกล่องโต้ตอบคือ
   `PDF files (*.pdf)` และมีตัวเลือก `All files (*.*)` ให้เลือกด้วย หรือ **ลากแล้ววาง**
   ไฟล์ PDF หนึ่งไฟล์ลงบนหน้าต่าง
3. เอกสารจะเปิดในมุมมองต่อเนื่อง (ค่าเริ่มต้นคือ Fit Width) และแถบสถานะจะแสดง
   `file.pdf   N / M   Z%` คือ หน้าปัจจุบัน / จำนวนหน้าทั้งหมด / ระดับซูม

**การเปิดโดยตรงจาก command line.** คุณยังสามารถเปิด PDF หนึ่งไฟล์ได้ทันทีตอนเปิดโปรแกรม
โดยส่งพาธของไฟล์เป็นอาร์กิวเมนต์แรก:

    FastPDF.exe "C:\Users\me\My Folder\report.pdf"

พาธอาจมีช่องว่างและอักขระ Unicode ได้ โดยครอบด้วยเครื่องหมายคำพูดตามตัวอย่าง
เฉพาะอาร์กิวเมนต์แรกเท่านั้นที่ใช้เป็นเอกสารที่จะเปิด ส่วนอาร์กิวเมนต์อื่น ๆ จะถูกเพิกเฉย
การเรียก `FastPDF.exe` โดย**ไม่มี**อาร์กิวเมนต์จะเปิดหน้าต่างว่างตามปกติ (พร้อมใช้
**Ctrl+O** หรือลากวาง) และจะไม่พยายามเปิดตัวโปรแกรมเองเป็น PDF พาธที่หาไม่พบหรืออ่านไม่ได้
จะแสดงข้อความผิดพลาดแบบเดียวกับการเปิดจากกล่องโต้ตอบ (ดูตารางด้านล่าง)

การลากวางไฟล์ภาพที่รองรับ (`.png`, `.jpg`, `.jpeg`, `.bmp`) เพียงไฟล์เดียวจะเปิดกล่องโต้ตอบ Image to PDF แทน และการวางหลายไฟล์พร้อมกันจะเปิด Image to PDF ด้วยไฟล์ภาพที่รองรับในชุดนั้น ส่วนไฟล์ PDF และไฟล์ชนิดอื่นที่ถูกวางพร้อมกันจะถูกเพิกเฉย

เมื่อเปิดเอกสารไม่ได้ โปรแกรมจะแสดงข้อความใดข้อความหนึ่งจากตารางนี้
(มาจากฟังก์ชัน `AppWindow::UserMessageForError`):

| สถานการณ์ | ข้อความที่แสดง |
| --- | --- |
| ไม่พบไฟล์ | `The file could not be found.` |
| อ่านไฟล์ไม่ได้ | `The file could not be read.` |
| ไฟล์เสียหรือไม่ใช่ PDF | `The PDF could not be opened. It may be damaged or not a PDF.` |
| ไฟล์ตั้งรหัสผ่าน | `This PDF requires a password.` |
| ใช้ระบบป้องกันที่ไม่รองรับ | `This PDF uses an unsupported security scheme.` |
| build แบบไม่รวม PDFium | `PDF support is not available in this build.` |

## การอ่าน การเลื่อน และการซูม

- **เลื่อน** ด้วยล้อเมาส์ **Page Up / Page Down** ไปหน้าถัดไป/ย้อนกลับหนึ่งหน้า
  **Home / End** ไปหน้าแรกและหน้าสุดท้าย
- **ซูม**: **Ctrl + ล้อเมาส์** จะซูมโดยยึดตำแหน่งใต้ตัวชี้ **Ctrl+0** = Fit Page,
  **Ctrl+1** = 100% และ **Ctrl+2** = Fit Width ระดับซูมอิสระถูกจำกัดไว้ที่ 25%–800%
- **Page anchor**: ตำแหน่งตามเหตุผลใต้กรอบมองจะถูกคงไว้เมื่อซูม เมื่อปรับขนาดหน้าต่าง และเมื่อย้ายหน้าต่างไปยังจอที่มี DPI ต่างกัน
- Fit Width / Fit Page ในโหมดอ่านจะคำนวณตาม **หน้าแรก** ของเอกสาร (พฤติกรรม
  "พอดีเอกสาร" แบบมาตรฐาน) ส่วนในโหมดนำเสนอแต่ละหน้าจะถูกจัดให้พอดีกับกรอบมองของจอ

## การค้นหาข้อความในเอกสาร

- กด **Ctrl+F** (หรือ **View > Find...**) เพื่อเปิดแผงค้นหาแบบไม่บล็อกที่มุมขวาบน ประกอบด้วยช่องข้อความ ตัวนับผลแบบ `current / total` ปุ่ม `<` `>` และปุ่มปิด
- การค้นหาทำงานแบบทันทีที่พิมพ์ (incremental) บนเธรด worker พื้นหลังผ่าน API
  `FPDFText_*` ของ PDFium จึงไม่ทำให้ UI หยุดชะงัก และเมื่อพิมพ์อักขระเพิ่ม ระบบจะยกเลิกงานค้นหาก่อนหน้าทันที
- นำทางระหว่างผลลัพธ์ด้วยปุ่ม `<` / `>` บนแผง หรือด้วย Enter / Shift+Enter และปิดแผงได้ด้วยปุ่มปิดหรือ **Esc**
- ช่องข้อความค้นหาและปุ่มของแผงส่งคำสั่งต่อไปยังหน้าต่างหลักด้วยตัวส่งต่อคำสั่ง (command forwarder) ที่ติดตั้งบนแผง การพิมพ์และการคลิกจึงสั่งงานการค้นหาได้จริง การเชื่อมต่อนี้ยืนยันด้วยรายการทดสอบอัตโนมัติ `fastpdf_search_ui_routing_tests` เท่านั้น ยังไม่ได้ทดสอบการใช้งานจริงบนหน้าจอด้วยมือ
- ผลการค้นหาเก็บเป็นช่วงอักขระขนาดเล็ก จำกัดไว้ที่ 5,000 รายการ
  (`kMaxSearchResults`) และจะคำนวณกรอบตำแหน่งเฉพาะผลที่มองเห็นหรือผลที่เลือกอยู่เท่านั้น ผลที่เลือกจะถูกไฮไลต์ด้วยสีเหลืองอมส้ม ผลอื่นที่มองเห็นเป็นสีเหลืองโปร่งแสง
- เอกสารประเภทสแกนหรือไม่มีชั้นข้อความจะให้ผล 0 รายการอย่างเรียบร้อย

## โหมดนำเสนอ

- กด **F11** (หรือ **View > Present**) เพื่อเข้าสู่เต็มจอไร้ขอบทันที โดยจัดหน้าปัจจุบันให้พอดีกับกรอบมอง
- เปลี่ยนสไลด์ด้วย **Right / Down / Space / Page Down / ล้อเมาส์ลง / คลิกซ้าย**
  ถอยกลับด้วย **Left / Up / Page Up / ล้อเมาส์ขึ้น** และกระโดดด้วย **Home / End**
- หน้าข้างเคียงถูกเรนเดอร์ล่วงหน้า การเปลี่ยนหน้าที่มีในแคชจึงใช้เวลาน้อยมาก
- ออกจากโหมดด้วย **Esc** หรือ **F11** แล้วโปรแกรมจะคืนค่าตำแหน่งหน้าต่าง รูปแบบ ตำแหน่งเลื่อน และระดับซูมเดิมทั้งหมด

## การจับภาพหน้าเอกสาร

- กด **Ctrl+S** (หรือ **View > Screenshot**) แล้วลากกรอบเลือกบนเอกสาร กรอบที่เลือกจะคร่อมหลายหน้าก็ได้
- ภาพที่ได้มาจากการประกอบเนื้อหาหน้าที่เรนเดอร์แล้วบน bitmap นอกจอเท่านั้น ไม่จับแถบเครื่องมือ กล่องโต้ตอบ หรือหน้าต่างอื่น พื้นที่ใดที่ยังเรนเดอร์ไม่เสร็จจะเป็นสีขาว และจะใช้ภาพ preview ที่มีอยู่ระหว่างรอภาพคุณภาพเต็ม
- ผลลัพธ์ถูกวางลงคลิปบอร์ดทั้งในรูปแบบ `CF_DIBV5` และ PNG และบันทึกเป็นไฟล์ PNG ได้ในขั้นตอนเดียว

## การแปลง PDF เป็น PNG

เมนู **Convert > PDF to PNG...** ส่งออกหน้าเอกสารเป็นไฟล์ PNG

- โหมดเลือกหน้า: **All** (ทุกหน้า) **Current** (หน้าปัจจุบัน) หรือ **Custom** ระบุช่วงเช่น
  `1-5, 8, 10` (ระบบจะแปลงค่า เรียงลำดับ ลบซ้ำ และจำกัดให้อยู่ในช่วงจำนวนหน้าจริง)
- คุณภาพ: **Standard = 150 DPI**, **High = 300 DPI**
- ชื่อไฟล์ผลลัพธ์กำหนดได้แน่นอนและเติมเลขศูนย์ เช่น `doc_page_001.png`
- ทำงานบนเธรด worker มีแถบความคืบหน้าและยกเลิกได้ เขียนผ่านไฟล์ชั่วคราว และ
  **ไม่เขียนทับไฟล์ที่มีอยู่เดิม**

## การแปลงภาพเป็น PDF

เมนู **Convert > Image to PDF...** (หรือลากวางไฟล์ภาพบนหน้าต่าง) สร้าง PDF หนึ่งไฟล์จาก PNG / JPEG / JPG / BMP

- จัดลำดับรายการภาพใหม่ก่อนแปลงได้
- แต่ละหน้าใช้กระดาษ A4 ขอบคงที่ขนาดเล็ก เลือกทิศทางอัตโนมัติ (แนวนอนเมื่อภาพกว้างกว่าสูง) คงสัดส่วนภาพไว้ วางกึ่งกลาง และไม่ยืดภาพ
- จัดการช่อง alpha อย่างปลอดภัย เขียนผลลัพธ์แบบ atomic ไม่ทับไฟล์เดิม และยกเลิกได้จากกล่องโต้ตอบความคืบหน้าที่ไม่บล็อก UI

## การพิมพ์

**File > Print...** หรือ **Ctrl+P** (ใช้ได้เมื่อมีเอกสารเปิดอยู่):

- เลือกเครื่องพิมพ์แบบ native ระบุได้ทั้งเครื่องพิมพ์ในระบบและบนเครือข่าย
- ช่วงหน้า: `All`, `Current` หรือ `Custom` (เช่น `1-3, 5`)
- ระบุขนาดกระดาษตามที่มีจริงในแต่ละเครื่องพิมพ์ โดยสำรองเป็น A4 เมื่อมีให้เลือก
- การขยาย: `Fit` (รักษาสัดส่วน เคารพขอบเขตที่เครื่องพิมพ์พิมพ์ไม่ได้) หรือ
  `Actual Size` (100% พร้อมเตือนหากเนื้อหาเกินขอบเขตที่พิมพ์ได้)
- ทิศทาง: `Auto` (ตามสัดส่วนของหน้า) `Portrait` `Landscape`
- จำนวนสำเนา: 1–999
- ตัวอย่างก่อนพิมพ์ใช้โมเดล `PrintLayout` ตัวเดียวกับที่ใช้ตอนส่งพิมพ์จริง
- การส่งพิมพ์ทำงานนอกเธรด UI มีแถบความคืบหน้า ยกเลิกได้ (`AbortDoc`) และรายงานข้อผิดพลาด หน้าเอกสารถูกเรนเดอร์เป็นเวกเตอร์ผ่าน PDFium ลง printer DC โดยมีตัวสำรองเป็นการเรนเดอร์แบบ raster ความละเอียดสูงเมื่อจำเป็น

## ไฟล์ที่เปิดล่าสุด

- **File > Recent Files** แสดงเอกสารที่เปิดล่าสุดได้สูงสุด 10 รายการ และ
  **Clear Recent Files** จะล้างรายการทั้งหมด
- แต่ละรายการเก็บพาธ เวลาที่เปิดล่าสุด ดัชนีหน้าสุดท้าย จุด anchor การมอง โหมดซูม และระดับซูม เมื่อเปิดซ้ำจึงกลับสู่ตำแหน่งเดิม
- บันทึกลง `%LOCALAPPDATA%\FastPDF\recent.dat` ด้วยการเขียนแบบ atomic
  (`recent.tmp` → `MoveFileExW`)
- ไฟล์ที่หายหรืออ่านไม่ได้จะแจ้งให้ผู้ใช้ทราบและถูกตัดออกจากรายการ

## แผงข้อมูลวินิจฉัย

- กด **Ctrl+D** เพื่อต่อท้ายแถบสถานะด้วยตัวเลขการทำงานแบบสด:
  `[DIAG: Q=<queue> Cache=<KB> (<hit>%) Frame=<ms>]`
- ตัวเลขที่วัดได้แก่ เวลาเริ่มโปรแกรม เวลาเปิดและอ่านโครงสร้างเอกสาร เวลาเรนเดอร์หน้าแรกที่มองเห็น เวลาเรนเดอร์รายหน้าและคุณภาพที่ใช้ ความลึกของคิวงาน ขนาดและอัตราการพบข้อมูลในแคช LRU เวลาเปลี่ยนหน้าในโหมดนำเสนอ และเวลาเรนเดอร์หนึ่งเฟรมของ Direct2D
- แผงนี้ปิดเป็นค่าเริ่มต้น มีไว้สำหรับผู้พัฒนาและการรายงานข้อผิดพลาด

| พาธ | วัตถุประสงค์ |

| `%LOCALAPPDATA%\FastPDF\recent.dat` | รายการไฟล์ที่เปิดล่าสุด (พาธ หน้า จุด anchor การมอง ระดับซูม) |

## การสร้างโปรแกรมจากซอร์ส

### 1. ดาวน์โหลดและตรวจสอบอาร์ติแฟกต์ PDFium เวอร์ชันตรึง

อ่านสัญญาการ integrate ก่อน:
[`third_party/pdfium/PDFIUM_LOCK.md`](third_party/pdfium/PDFIUM_LOCK.md)
**repository นี้ไม่ได้รวมหรืออ้างสิทธิ์ในอาร์ติแฟกต์ PDFium ใด ๆ** — คุณต้องจัดหาและตรวจสอบเอง

1. ดาวน์โหลด `pdfium-win-x64.tgz` (รุ่น non-V8) จาก release tag `chromium/8035`
   ของ [pdfium-binaries releases](https://github.com/bblanchon/pdfium-binaries/releases)
   อย่างเป็นทางการ พร้อมไฟล์ `pdfium-attestation.json`
2. แตกอาร์ติแฟกต์ไปไว้ภายนอก repository เช่น `C:\deps\pdfium` โดยต้องมี
   `include\fpdfview.h`, `lib\pdfium.dll.lib` และ `bin\pdfium.dll`
3. ตรวจสอบโครงสร้างและพิมพ์ค่าแฮช SHA-256 ของ `pdfium.dll`:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\verify_pdfium.ps1 `
       -PdfiumRoot C:\deps\pdfium
   ```

4. เทียบแฮชที่ได้กับตารางใน `PDFIUM_LOCK.md` เพื่อบังคับใช้ตอน configure (จะส่ง
   `-ExpectedSha256` ให้สคริปต์ตรวจสอบด้วยก็ได้):

   ```powershell
   cmake --preset debug -DPDFIUM_ROOT=C:/deps/pdfium `
       -DPDFIUM_EXPECTED_SHA256=<sha256 ของ pdfium.dll>
   ```

ถ้าไม่ตั้ง `PDFIUM_ROOT` หรือตั้งแล้วไม่ถูกต้อง การ configure จะ **ล้มเหลว** พร้อมข้อความบอกวิธีแก้ไข และจะไม่ใช้ PDFium ที่มีอยู่ในระบบแบบเงียบ ๆ

### 2. Configure, build, test, run

จากโฟลเดอร์ root ของ repository (PowerShell):

```powershell
cmake --preset debug -DPDFIUM_ROOT=C:/deps/pdfium
cmake --build --preset debug
ctest --preset debug
.\build\debug\bin\Debug\FastPDF.exe
```

โหมด release ใช้ลำดับเดียวกัน:

```powershell
cmake --preset release -DPDFIUM_ROOT=C:/deps/pdfium
cmake --build --preset release
ctest --preset release
.\build\release\bin\Release\FastPDF.exe
```

ระบบจะคัดลอก `pdfium.dll` ไปวางข้าง `FastPDF.exe` อัตโนมัติตอน build และ target
`fastpdf_third_party_notices` จะคัดลอก `THIRD_PARTY_NOTICES.txt` ไปไว้ที่เดียวกัน

## ตัวเลือกขณะ configure

| ตัวแปร | ค่าเริ่มต้น | ผลลัพธ์ |
| --- | --- | --- |
| `FASTPDF_WITH_PDFIUM` | `ON` | build adapter PDFium ตัวจริง ถ้า `OFF` จะ compile stub และโปรแกรมแจ้งว่าไม่รองรับ PDF |
| `FASTPDF_BUILD_TESTS` | `ON` | build ตัวทดสอบและลงทะเบียนกับ CTest |
| `FASTPDF_BUILD_SMOKE` | `ON` | build ตัวทดสอบ smoke ของ PDFium (ต้องมี `FASTPDF_WITH_PDFIUM`) |
| `PDFIUM_ROOT` | ค่าจากตัวแปรสภาพแวดล้อม `PDFIUM_ROOT` | พาธของอาร์ติแฟกต์ที่แตกไฟล์และตรวจสอบแล้ว |
| `PDFIUM_EXPECTED_SHA256` | ว่าง | บังคับตรวจสอบแฮช SHA-256 ของ `pdfium.dll` ตอน configure |

presets ที่มี: `debug` และ `release` ทั้งคู่ใช้ generator `Visual Studio 17 2022`
architecture `x64` และไดเรกทอรีผลลัพธ์ `build/debug` กับ `build/release`
([`CMakePresets.json`](CMakePresets.json))

## การสร้างโดยไม่ใช้ PDFium

โครงสร้างหลักยัง build และรันได้โดยไม่มี PDFium แต่เมื่อเปิดไฟล์ PDF จะแสดงข้อความ
`PDF support is not available in this build.`:

```powershell
cmake --preset debug -DFASTPDF_WITH_PDFIUM=OFF
cmake --build --preset debug
ctest --preset debug
```

## การสร้างแพ็กเกจเผยแพร่

สคริปต์แพ็กเกจจะจัดเตรียม ZIP แบบพกพาสำหรับ x64 ที่มีการพึ่งพาน้อยที่สุด — ไม่มีตัวติดตั้ง:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\package_release.ps1 `
    -BuildDir build\release -DistDir dist -PdfiumRoot C:\deps\pdfium
```

หรือเรียกผ่าน custom target ของ CMake (target นี้ขึ้นกับ `FastPDF` จึงต้อง configure
ด้วย `PDFIUM_ROOT` ที่ถูกต้องก่อน):

```powershell
cmake --build --preset release --target fastpdf_package_release
```

โครงสร้างผลลัพธ์ใน `dist/FastPDF-<version>-win-x64/`:


## การเผยแพร่ไฟล์สำเร็จรูป

**repository นี้ไม่ได้เผยแพร่ไฟล์ที่ build สำเร็จรูป** ตาม commit ที่เอกสารนี้อ้างถึง

เวอร์ชันใน repository คือ `0.2.0` และชื่อแพ็กเกจที่สร้างในเครื่องคือ
`FastPDF-0.2.0-win-x64.zip` ซึ่งไฟล์นั้นมีอยู่เฉพาะบนเครื่องที่ build เท่านั้น

## กฎการครอบครองทรัพยากรและเธรด

กฎการครอบครองและเธรด (บังคับด้วยโครงสร้างของโค้ด ไม่ใช่แค่ข้อกำหนด):

- เธรด UI ครอบครอง HWND และทรัพยากร Direct2D/DirectWrite ทั้งหมด การแปลง bitmap บน
  CPU เป็น `ID2D1Bitmap` ทำบนเธรด UI เท่านั้น และทั้งแคช LRU บน CPU ที่จำกัดด้วยไบต์กับแคช D2D ที่จำกัดขนาดล้วนเป็นของเธรด UI
- `RenderWorker` เป็นเธรดทำงานถาวรเพียงเธรดเดียว ครอบครองการเข้าถึงเอกสาร PDFium
  **ทั้งหมด**: `PdfDocument` ถูกเปิด ใช้เรนเดอร์ทุกหน้า และทำลายบนเธรดนี้ ส่งกลับมายัง UI เฉพาะข้อมูลที่เป็นค่า (bitmap, ผลลัพธ์) ไม่มีการแชร์ handle ของ
  `FPDF_DOCUMENT` หน้า หรือ bitmap ข้ามเธรด และการเรียก PDFium ดิบทุกจุดยังถูกลำดับผ่าน call gate ระดับโปรเซส
- priority scheduler ที่จำกัดขนาดและรวมงานเป็นผู้เก็บงานเรนเดอร์ที่รอคิว (ไม่มีคิวแบบไม่จำกัด) epoch ของเอกสาร/มุมมอง และ id ของงานทำให้ UI รับเฉพาะผลลัพธ์ของเอกสาร มุมมอง และ key ปัจจุบัน แล้วทิ้งผลลัพธ์ที่ล้าสมัย
- การจัดวางต่อเนื่องเป็นคณิตศาสตร์ล้วน ๆ ใน `fastpdf_core` (ไม่พึ่ง PDFium หรือ
  Windows) UI จะสร้างใหม่ทุกครั้งที่ซูมหรือเปลี่ยน viewport และขอเรนเดอร์หน้าที่มองเห็นกับหน้าข้างเคียงที่คุณภาพ preview หรือ final
- header และสัญลักษณ์ PDFium ดิบมีอยู่เฉพาะใน `fastpdf_pdfium`
- ไม่มีการ parse หรือแปลงเป็นภาพ (rasterize) บนเธรด UI

## ประสิทธิภาพ

ตัวเลขเหล่านี้วัดจาก fixture หลายหน้าแบบ deterministic อัตโนมัติและการรัน smoke บน UI
จริง บนเครื่องอ้างอิงเพียงเครื่องเดียวที่ใช้ Windows 11 x64 (Intel Core i7 gen 12,
NVMe SSD, Direct2D เร่งด้วยฮาร์ดแวร์) **นี่คือสิ่งที่สังเกตได้ ไม่ใช่การรับประกัน**
ผลลัพธ์จริงขึ้นกับ CPU ความละเอียดจอ ความซับซ้อนของเอกสาร และ I/O ของ storage

| ตัวชี้วัด | เป้าหมาย | ผลที่วัดได้บนเครื่องนั้น |
| --- | --- | --- |
| เวลาเริ่มโปรแกรม | < 300 ms จนโต้ตอบได้ | ~45 ms (เริ่ม COM และ D2D พร้อมเริ่ม worker) |
| เวลาเปิดไฟล์ PDF | < 100 ms กับเอกสารทั่วไป | ~3–12 ms (fixture 3–4 หน้าที่สร้างเอง) |
| เวลาเรนเดอร์หน้าที่มองเห็นเป็นหน้าแรก | < 150 ms | ~25–60 ms (รวมการจัดคิวงานของ worker) |
| เวลาเรนเดอร์รายหน้า | < 80 ms ต่อหน้า (คุณภาพเต็ม) | ~2–20 ms (หน้าความซับซ้อนมาตรฐาน) |
| เวลาเปลี่ยนสไลด์ | < 1 ms เมื่อเรนเดอร์ล่วงหน้าไว้ | < 0.1 ms (อ่านจากแคช) |
| อัตราการพบข้อมูลในแคช (cache hit) | > 80% ระหว่างเลื่อนต่อเนื่อง | 85%–95% ในการท่องเอกสารหลายหน้า |
| ความลึกคิวของ scheduler | จำกัดอย่างเคร่งครัด (<= 16) | 0–4 งานขณะใช้งานจริง |
| การใช้ CPU ขณะว่าง | 0% (ไม่มี busy-loop หรือการวาดต่อเนื่อง) | 0.0% ขณะว่าง วาดตาม `WM_PAINT` เมื่อจำเป็น |
| เวลาเรนเดอร์หนึ่งเฟรมของ D2D | < 16.6 ms (60 FPS ลื่น) | ~0.5–2.5 ms ต่อ draw call |

**เครื่องมือวัดประสิทธิภาพ (benchmark harness).** `scripts/benchmark_startup.ps1`
จำลองการวัดเวลาเริ่มโปรแกรม/เปิดไฟล์/เฟรมแรกแบบ direct-CLI โดยเรียก
`FastPDF.exe <pdf>` พร้อมเปิดใช้เครื่องมือวัด `FASTPDF_BENCHMARK` แล้วเก็บผลลัพธ์
JSON ของแต่ละเฟสข้ามหลายรอบ สคริปต์นี้วัด**เฉพาะเฟสของ FastPDF เอง** และ**ไม่ได้**
เปรียบเทียบกับโปรแกรมอื่น การเปรียบเทียบข้ามผลิตภัณฑ์ต้องใช้วิธีที่ตรงกันนอกสคริปต์นี้
ตัวเลขเหล่านี้เป็นสิ่งที่สังเกตได้บนเครื่องเดียว ไม่ใช่การรับประกัน และ**ไม่ใช่**การอ้างว่า
FastPDF เร็วกว่า SumatraPDF หรือโปรแกรมดู PDF อื่นใด

## ข้อจำกัดที่ทราบ

- การเรนเดอร์เป็นเธรดเดียวตามการออกแบบ: ใช้ PDFium renderer ตัวเดียวเรียงลำดับ พร้อม
  call gate ระดับโปรเซสที่ห้ามเรนเดอร์พร้อมกันภายในโปรเซส หน้าที่ใช้เวลาเรนเดอร์นานจึงต้องรอคิวหลังงานปัจจุบัน แต่ UI ไม่บล็อก และหน้าที่มองเห็นจะเรนเดอร์เป็นคุณภาพ
  preview ขนาดครึ่งก่อนเสมอ
- ไฟล์ PDF ที่ตั้งรหัสผ่านจะแสดง `This PDF requires a password.` — ยังไม่มีกล่องให้กรอกรหัสผ่าน
- Fit Width / Fit Page ในโหมดอ่านคำนวณตาม **หน้าแรก** ของเอกสาร
- เอกสารจะถูก parse ใหม่เมื่อเปิดไฟล์อื่นเท่านั้น เอกสารเดิมจะเปิดค้างไว้ตลอดการเรนเดอร์ทุกหน้า
- การลากวางจะทำงานกับไฟล์เดียวต่อการเปิดหนึ่งครั้ง: ไฟล์ PDF เดียวจะเปิดในผู้ชม และไฟล์ภาพเดียวที่รองรับ (PNG, JPEG, JPG, BMP) จะเริ่มการแปลงภาพเป็น PDF ส่วนการวางหลายไฟล์จะเริ่มการแปลงภาพเป็น PDF โดยใช้เฉพาะไฟล์ภาพที่รองรับในชุดนั้น (ไฟล์ PDF และชนิดอื่นที่ถูกวางพร้อมกันจะถูกเพิกเฉย)
- การค้นหาทำงานกับชั้นข้อความเท่านั้น ไม่มี OCR หน้าสแกนจึงไม่พบผลลัพธ์
- ไม่มีการรวมอาร์ติแฟกต์ PDFium ไว้ในโปรเจกต์ อาร์ติแฟกต์ถูกเก็บในเครื่องภายนอก
  repository (เช่น `C:\deps\pdfium`) และตรวจสอบกับ SLSA provenance ที่เผยแพร่พร้อม
  release เวอร์ชันตรึง
  ([`third_party/pdfium/PDFIUM_LOCK.md`](third_party/pdfium/PDFIUM_LOCK.md))
- การพิมพ์จริงทดสอบผ่าน print spooler แบบ native ของ Windows และ
  **Microsoft Print to PDF** ยังไม่ได้ทดสอบการพิมพ์ลงเครื่องพิมพ์หมึกหรือเลเซอร์จริงในการรันอัตโนมัติ
- ไม่มีไฟล์ที่ build สำเร็จรูปเผยแพร่ใน repository นี้
  ([การเผยแพร่ไฟล์สำเร็จรูป](#การเผยแพร่ไฟล์สำเร็จรูป))

## บันทึกการตรวจสอบ

ผลลัพธ์ข้างล่างนี้ผู้ดูแลบันทึกไว้บนเครื่องที่อธิบายในหัวข้อ
[ประสิทธิภาพ](#ประสิทธิภาพ) และไม่ได้รันอัตโนมัติด้วยบริการ CI ใด ๆ ใน repository นี้

1. ตรวจสอบ PDFium เวอร์ชันตรึงด้วย `scripts/verify_pdfium.ps1` เทียบกับ
   `third_party/pdfium/PDFIUM_LOCK.md`
2. build แบบ debug พร้อม PDFium: `cmake --preset debug` →
   `cmake --build --preset debug` → `ctest --preset debug` (ผ่าน 24/24 รายการ)
3. build แบบ release พร้อม PDFium: `cmake --preset release` →
   `cmake --build --preset release` → `ctest --preset release` (ผ่าน 24/24 รายการ)
4. build แบบ release โดยไม่ใช้ PDFium:
   `cmake -B build/release-off -DFASTPDF_WITH_PDFIUM=OFF` →
   `cmake --build build/release-off --config Release` →
   `ctest --test-dir build/release-off -C Release` (ผ่าน 13/13 รายการในการบันทึกครั้งนั้น การตั้งค่านี้ลงทะเบียน 15 รายการในปัจจุบัน และยังไม่ถูกรันใหม่นับตั้งแต่เพิ่มรายการทดสอบการส่งต่อคำสั่งและการเปิดจาก command line ที่ไม่พึ่งพา PDFium)
5. สร้างแพ็กเกจพกพา:
   `cmake --build --preset release --target fastpdf_package_release`
    → ได้ `dist/FastPDF-0.2.0-win-x64.zip` พร้อม MANIFEST แบบ SHA-256
6. ทดสอบการรัน: `dist/FastPDF-0.2.0-win-x64/FastPDF.exe` เปิด ทำงาน และปิดได้เรียบร้อย
7. การส่งต่อคำสั่งของแผงค้นหา: `fastpdf_search_ui_routing_tests` (4 กรณีทดสอบ) พิสูจน์ว่าแผงกลืน `WM_COMMAND` ที่คอนโทรลลูกส่งมาเมื่อไม่มีตัวส่งต่อ และส่งคำสั่งจากปุ่มปิดกับ `EN_CHANGE` ของช่องข้อความไปถึงหน้าต่างหลักเมื่อติดตั้งตัวส่งต่อแล้ว เป็นหลักฐานจากการทดสอบอัตโนมัติที่ระดับ window procedure เท่านั้น ไม่ได้ทดสอบการใช้งานจริงบนหน้าจอด้วยมือ

## การมีส่วนร่วมพัฒนา

repository นี้ยังไม่มีไฟล์ `CONTRIBUTING.md` ไม่มีเทมเพลต pull request และไม่มี workflow
CI สิ่งที่มีหลักฐานอยู่ในโปรเจกต์มีดังนี้

- **Issue tracker** — เปิดใช้ GitHub Issues ที่
  <https://github.com/underoatz-netizen/FastPDF> ควรระบุเวอร์ชัน Windows ว่า build ของคุณรวม PDFium หรือไม่ และค่า `[DIAG: ...]` จากหัวข้อ
  [แผงข้อมูลวินิจฉัย](#แผงข้อมูลวินิจฉัย) เมื่อเกี่ยวข้อง อย่าแนบเอกสารที่คุณไม่มีสิทธิ์เผยแพร่ เพราะการทดสอบใช้ fixture ที่สร้างเอง ไม่ใช้ไฟล์จริง
- **เกณฑ์ build และทดสอบ** — การแก้ไขควรทำให้ทั้งสองการตั้งค่าผ่านครบ:
  `ctest --preset debug` และ `ctest --preset release` แบบมี PDFium (24 รายการ) และการตั้งค่า `-DFASTPDF_WITH_PDFIUM=OFF` (15 รายการ)
- **ขอบเขตสถาปัตยกรรม** — คงการใช้ PDFium ดิบไว้เฉพาะใน `src/pdfium/` คงคณิตศาสตร์การจัดวางให้เป็นโค้ดอิสระใน `src/core/` และเข้าถึง PDFium บนเธรด `RenderWorker`
  เท่านั้น ([กฎการครอบครองทรัพยากรและเธรด](#กฎการครอบครองทรัพยากรและเธรด))
- **การเปลี่ยนเวอร์ชันตรึงของ PDFium** — ต้องแก้ไข
  `third_party/pdfium/PDFIUM_LOCK.md` ใน commit เดียวกันและรันขั้นตอนตรวจสอบใหม่
- **เอกสารสิทธิ์** — เมื่อเพิ่ม dependency หรือไลเซนส์เปลี่ยน ให้แก้
  `THIRD_PARTY_NOTICES.md` ในการแก้ไขเดียวกัน
- **สไตล์โค้ด** — โปรเจกต์ build ด้วย `/W4 /permissive- /Zc:__cplusplus /utf-8` และ
  C++20 คาดว่าต้องไม่มีคำเตือนคงค้าง
